# 商品浏览历史（足迹）功能开发文档

## 1. 需求概述

为商城 C 端用户提供"商品浏览历史"（足迹）功能：

- 用户每浏览一个商品详情页，系统记录该商品的浏览记录。
- 用户在个人中心（/me）内可查看自己的浏览历史，按时间倒序展示。
- 支持删除单条、清空全部浏览记录；点击记录可跳回商品详情页。
- **仅支持登录用户**：记录归属于登录用户；**不支持游客态**，未登录不产生/不展示浏览历史。
- 浏览历史中的商品**即使已下架也保留展示**，但要在前端提示"该商品已下架"。
- 不展示"XX 人看过"等字数浏览量统计。
- 单用户浏览历史设置**最大保留条数**，超过后自动淘汰最旧的记录。

> 与现有"搜索/推荐埋点"（`stellar_user_behavior`，只追加、用户不可见、不删除）不同，浏览历史是**用户可见、可管理**的数据，因此独立设计。

## 3. 方案设计

### 3.1 数据存储方案（选 B）

**方案 A：复用 `stellar_user_behavior`（弃用）**
- 优点：零新表。
- 缺点：该表语义是"只追加埋点、不改不删"，且按设备归因、游客也会写，无法承载"用户可见、可删、可清空"的浏览历史。故不采用。

**方案 B：独立浏览历史表（采用）**
- 新增 `stellar_browse_history` 表，`(user_id, spu_id)` 唯一，浏览时**去重更新**时间。
- 语义清晰：登录用户的浏览足迹、可删可清空、按时间倒序分页。
- 浏览详情时不影响商品、订单主链路（写入异步 + 失败静默）。

### 3.2 数据表设计（Flyway V23）

```sql
-- V23__browse_history.sql
CREATE TABLE IF NOT EXISTS stellar_browse_history (
    id           BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '主键',
    user_id      BIGINT          NOT NULL                COMMENT '登录用户 ID',
    spu_id       BIGINT          NOT NULL                COMMENT '商品 SPU ID',
    sku_id       BIGINT          DEFAULT NULL            COMMENT '浏览时的 SKU ID（可选）',
    browse_time  DATETIME        NOT NULL                COMMENT '最近浏览时间',
    create_time  DATETIME        NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '首次浏览时间',
    PRIMARY KEY (id),
    UNIQUE KEY uk_browse_user_spu (user_id, spu_id),
    KEY idx_browse_user_time (user_id, browse_time)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='商品浏览历史（用户足迹）';
```

要点：
- `(user_id, spu_id)` 唯一 + `browse_time` 刷新，同一商品重复浏览只保留最新一次，避免足迹膨胀。
- 索引 `idx_browse_user_time` 支撑按用户倒序分页。

## 4. 后端实现

### 4.1 记录浏览

**写入时机**：在 `UserSpuController#detail` 成功返回商品后异步写入（参考 `BehaviorController` 的"失败静默 + @Async"模式）。

不侵入 `SpuService#getById` 主逻辑，采用独立 Service + @Async，保证浏览历史写入异常绝不影响商品详情接口。

新增模块（参考 `UserBehaviorServiceImpl` 的异步模式）：

```
com.stellar
 ├─ entity/BrowseHistory.java                          # 实体
 ├─ mapper/BrowseHistoryMapper.java                    # Mapper 接口
 ├─ resources/mapper/BrowseHistoryMapper.xml          # SQL（upsert）
 ├─ service/BrowseHistoryService.java                 # 接口
 ├─ service/impl/BrowseHistoryServiceImpl.java        # 实现（@Async 写入）
 ├─ controller/user/BrowseHistoryController.java      # C 端接口
 ├─ dto/SpuHistoryQueryDTO.java                       # 分页查询参数
 └─ vo/BrowseHistoryVO.java                           # 返回给前端（含商品快照）
```

**upsert 写入 SQL**：

```sql
INSERT INTO stellar_browse_history (user_id, spu_id, sku_id, browse_time)
VALUES (#{userId}, #{spuId}, #{skuId}, NOW())
ON DUPLICATE KEY UPDATE browse_time = NOW(), sku_id = VALUES(sku_id);
```

**最大保留条数（淘汰最旧）**：

单用户浏览历史最多保留 `BROWSE_HISTORY_LIMIT` 条（建议默认 **100**，做成常量/配置）。写入成功后若超出上限，删除该用户最旧的超额记录：

```sql
DELETE h FROM stellar_browse_history h
JOIN (
    SELECT id FROM stellar_browse_history
    WHERE user_id = #{userId}
    ORDER BY browse_time DESC
    LIMIT 1 OFFSET #{limit}        -- 保留前 limit 条，删掉第 limit+1 条及之后
) d ON h.id = d.id;
```

> 说明：UPSERT 每次最多新增 1 条，因此只需删除最旧的 1 条即可回到上限之内，无需批量清理。

### 4.2 接口设计（C 端，`/user/browse`，需登录）

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/user/browse/{spuId}` | 记录一次浏览（由详情页调用；入参可选 `skuId`） |
| GET | `/user/browse/page` | 分页查询浏览历史（倒序），返回商品快照：spuId、主图、标题、价格、浏览时间 |
| DELETE | `/user/browse/{id}` | 删除单条浏览记录 |
| DELETE | `/user/browse/clear` | 清空我的全部浏览记录 |

说明：
- 所有接口从 `BaseContext.getCurrentId()` 取 `userId`，禁止越权读取他人数据。
- 浏览在 `UserSpuController#detail` 返回成功（商品上架）后记录，故写入时无需再校验商品状态。
- `GET /user/browse/page` **不过滤下架/已删除商品**：通过 LEFT JOIN 商品表带回商品 `status`，前端据此对"已下架"商品做提示（下架/删除时标题、图片可能缺失，VO 需做兜底，如标题回退"该商品已下架"、图片为空占位）。

### 4.3 实现要点与约束（对照项目 Memory 约定）

- 新增表用 Flyway：文件名 `V23__browse_history.sql`，放入 `db/migration`。
- 浏览历史写入使用 Controller 内**待确认埋点既有的可选解析**还是受保护接口？——因需登录，本功能走受保护接口（**必须登录**），统一由 JWT 拦截器注入 userId，保证数据归属正确。给详情页增加浏览写入时，若未登录则不调用该接口。
- Service 层创建记录遵循项目约定（如需审计字段则设 createUser；本表无审计字段，仅记录 user_id）。
- 浏览历史写入是异步 + 拼命而为（失败静默），但**淘汰删除应与写入同事务/同方法内串行**，确保上限生效。
- 浏览历史分页 SQL 按 `browse_time DESC, id DESC` 排序，保证同秒记录顺序稳定。
- `BROWSE_HISTORY_LIMIT` 定义为常量（如 `BrowseHistoryConstants.MAX_KEEP = 100`），后续可调整为配置项。
- 保留商品详情缓存 `spu:detail` 不受浏览历史写入影响；浏览历史不触发缓存失效。
- 接口返回的浏览记录无需再用 `@Cacheable` 缓存（数据实时、按用户隔离）。

## 5. 前端实现

### 5.1 记录浏览（SpuDetail.vue）

- 在 `SpuDetail.vue` 的 `loadDetail()` 成功后，若用户已登录（`stores/user.ts` 判断），调用新增 `recordBrowse(spuId)` API 记录浏览；未登录则跳过。
- 记录请求失败静默处理，不影响详情展示。

### 5.2 浏览历史页面

- 新增页面 `src/views/user/BrowseHistory.vue`，功能：
  - 商品卡片网格/列表，展示主图、标题、价格、最近浏览时间。
  - 点击卡片跳转 `/spu/:id`。
  - 单条删除（带确认）、右上角"清空全部"。
  - 分页加载或"加载更多"。
- **已下架/已删除商品**：根据接口返回的商品 `status` 判定——
  - 对已下架商品，卡片置灰，叠加标记（如"已下架"角标/遮罩），并在点击跳转后于详情页正常提示"该商品已下架"。
  - 标题/图片缺失时展示占位（标题回退"该商品已下架"，图片用默认占位图）。
  - 不清除记录（保留足迹），用户可自行删除。
- 样式可参考 `SpuDetail.vue` / 列表页卡片风格，与现有 C 端 UI 一致。

### 5.3 API 封装

- 在 `src/api/mall.ts` 新增（沿用 `userRequest` 模式）：
  - `recordBrowse(spuId, skuId?)`
  - `pageBrowseHistory(params)` → 分页浏览历史
  - `deleteBrowseHistory(id)`
  - `clearBrowseHistory()`
- 类型定义建议放 `src/types` 或在使用组件内联定义（参考现有约定）。

### 5.4 路由与入口

- 在 `src/router/index.ts` 用户路由段新增：

```ts
{
  path: '/me/browse',
  name: 'BrowseHistory',
  component: () => import('@/views/user/BrowseHistory.vue'),
  meta: { title: '浏览历史', requiresUserAuth: true }
},
```

- 在 `Profile.vue`（个人中心）/ 现有用户菜单入口中新增"浏览历史"入口（图标可选 `View` 或 `Clock`）。

## 8. 已确定设计决策

1. **不支持游客态**：浏览历史仅归属登录用户（`BaseContext.getCurrentId()`），未登录不记录、不展示。
2. **保留下架商品**：浏览历史中已下架/已删除商品仍展示，前端通过商品 `status` 判定并提示"该商品已下架"，用户可自行删除。
3. **不加浏览量统计**：仅个人足迹，无"XX 人看过"。
4. **单用户最大保留条数**：默认 100 条（常量 `MAX_KEEP`），超出自动淘汰最旧记录。
